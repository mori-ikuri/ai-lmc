1. 何をするシステムか
------------------------------------------------------------

  経理の請求業務。
  それまで田島さんが Excel(得意先請求管理.xls)で手でやっていた
  納品の明細→月の締め→請求書→入金 を、そのまま画面にしたもの。

  日本
    生産管理システム(2001年に外の業者が入れたもの。仕様書なし。業者は廃業)
      → 毎晩 受注CSVを共有フォルダに出す
      → 受注取込 (毎朝)
      → 納品入力 (納品書の控えを見て)
      → 締め処理 (月初、請求先ごと)
      → 請求書発行 (印刷して郵送)
      → 入金入力 (通帳を見て)

  タイ(現地法人 サンプル精機タイランド。2011年から)
    現地の生産管理が出す受注CSV
      → タイ受注取込
      → タイ納品入力
      → タイ締め (月末で全得意先まとめて)
    請求書は向こうで出しているので作らない。入金も無い。
    金額はバーツのまま。円には直していない。

  得意先ごとに 締め日・支払条件・丸め が違う。それを得意先マスタで持っている。

4. 画面 (メニューの並び順)
------------------------------------------------------------

  画面は全部 frmXxx.vb。作りは全部同じにしてある。
  Load → ボタン → 一覧 → 内部処理 の順に #Region で分けてある。
  DBは SqlConnection を開いて SQL文字列を組み立てて投げているだけ。
  「'」は EscQuote で二重にしている。取消は全部「区分を立てる」で、物理削除はどこにも無い。

  [日本]

  得意先登録 (frmTokuisaki / M_TOKUISAKI)
    コードは生産管理のCSVに出てくる得意先コードを手で入れる。
    締日は 末日・20日・25日 の3つだけ(経理のExcelにあるのがこの3つ。増えたら Load に足す)。
    末日はDBでは 31 で持っている。
    丸めは 切り捨て / 四捨五入。
    請求先: 納品先と請求書の宛先が違うとき、宛先の得意先コードを入れる。空なら自分あて。
            請求先も得意先として登録されている必要がある。自分自身は入れられない(空にする)。
    開始残高: Excelから移ったときの前回請求額。初めて締めるときだけ使う。
    備考: 「※請求書2部送付」のような注意書き。請求書発行の一覧に出る。
    使用しない: 受注も納品も残るので消さない。一覧から消えるだけ。

  単価登録 (frmTanka / M_TANKA)
    得意先×品番でひとつ。同じ品番でも得意先が違えば単価が違う。
    品名は請求書に出す名前。CSVの品名に品番がそのまま入っている行があるので、
    ここに品名が入っていればそちらを使う。
    単価は小数あり(212.5 など)。

  受注取込 (frmJuchuTorikomi / T_JUCHU, T_TORIKOMI_LOG)
    JUCHU_yyyymmdd.CSV を選んで取り込む。ヘッダ無し、9列、Shift-JIS。
      得意先 / 受注日(yyyyMMdd) / 納期 / 品番 / 品名 / 数量 / ? / 取消(N,C) / 伝票番号
    伝票番号がキー。
      新しい → 登録
      既にあって中身が同じ → 重複(何もしない)
      既にあって中身が違う → 訂正(上書き)。ただし納品済みなら上書きせず「要確認」に出す
      得意先マスタに無いコード → エラー(取り込まない)。先に得意先登録
    同じファイルを二度選ぶと確認が出る(T_TORIKOMI_LOG)。
    結果は一覧に出る。要確認とエラーがあればメッセージで知らせる。

  納品入力 (frmNohin / T_NOHIN)
    得意先を選ぶと受注一覧が出る(取消 C の受注は出ない)。受注を選んで数量を入れる。
    残っている数量が入っているので、分納なら打ち直す。
    単価と品名は単価マスタから来る。無ければ注意が出るので単価登録を先にする。
    金額 = 数量×単価。ここでは丸めない(小数のまま持つ)。
    受注数を超えると確認が出るが、止めない(多めに出ることがあるとのこと)。
    無償支給: チェックすると単価0。請求書では単価・金額が空欄になる。
    取消: 締め済み(SEIKYU_NOが入っている)は取り消せない。先に締め取消。

  締め処理 (frmShime / T_SEIKYU)
    年月を選ぶと請求先ごとに 期間・件数・今回売上額・前回請求額・入金額・繰越額・消費税・今回請求額 が出る。
    行を選んで「締める」。1件ずつ。
    締めると T_SEIKYU に1件でき、対象の納品に請求書番号(SEIKYU_NO)が書かれる。
    請求書番号が入った納品はもう拾わない。これが二重請求しないための目印。
    「初回」の列: その請求先をまだ一度も締めていない。前回請求額が開始残高から来るので確認が出る。
    「※締めの期間より前に、まだ請求していない納品が n 件あります」が出たら請求漏れ。
    締め取消: 納品を直したいときに使う。納品の請求書番号を消して、請求に取消区分を立てる。
              新しいほうから順にしか取り消せない(前回請求額がずれるため)。
              印刷済みなら「先方に送っていないか確かめて」の確認が出る。取り消した番号は欠番。

  請求書発行 (frmSeikyusho / T_SEIKYU, rptSeikyusho.rpt)
    年月で締め済みの請求が一覧に出る。「未印刷だけ」のチェックあり。
    表示 → 画面で見る。印刷 → 通常使うプリンタに1部出して印刷日を入れる。
    印刷済みならもう一度印刷するか確認が出る(二度出し防止)。
    一覧の右端に得意先の備考が出る。「2部送付」などはここを見て人がやる。
    ※印刷ボタンは1部しか出ない。2部要る得意先はコピーしている(田島さん)。

  入金入力 (frmNyukin / T_NYUKIN)
    請求先を選んで、入金日・金額・方法(振込/現金/手形/相殺/その他)・備考。
    どの納品・どの請求に充てるかは見ていない。請求先ごとに入った金額を記録するだけ。
    上に請求の一覧と「請求額 / その後の入金 / 残」が出る。残を超えると確認が出るが止めない。
    取消は区分。締め済みの請求に入っている入金を取り消すと請求書の入金額と合わなくなるので注意が出る。

  [タイ]

  タイ得意先登録 (frmThaiTokuisaki / M_TH_TOKUISAKI)
    現地のCSVにはコード(TH-0001 の形)しか無く、会社名がどこにも無い。名前はこちらで付ける。
    名前を付けていないコードも受注から拾って「(名前未登録)」で一覧に出る。

  タイ受注取込 (frmThaiTorikomi / T_TH_JUCHU)
    THJUCHU_*.CSV。ヘッダ無し、11列。日本と似ているが違う。
      得意先 / 受注日(dd/MM/yyyy) / 納期 / 品番 / 品名 / 数量 / 単価 / 通貨(THB) / ? / 状態 / 伝票番号
    日付が日/月/年なので自分で切って組み立てている(CDateに任せると月日を取り違える)。
    得意先が未登録でも取り込む(落とすと向こうのデータが手元に残らないので、知らせるだけ)。
    通貨が THB 以外なら一覧に出す(今まで来ていない)。
    納品済みの受注は内容が変わっていても上書きしない。日本と同じ。
    取込ログは日本と同じ表(T_TORIKOMI_LOG)。ファイル名が違うのでぶつからない。

  タイ受注一覧 (frmThaiJuchu)
    見るだけ。金額はバーツのまま。

  タイ納品入力 (frmThaiNohin / T_TH_NOHIN)
    日本の納品入力とほぼ同じ。違うところ:
      状態が X の受注は取り消されたものとみて出さない
      納品日は納期が初期値(実際にいつ出したかは分からないとのこと)。納期が空なら今日
      単価はCSVのもの(向こうで決めている単価)。打ち直せる
      金額は 数量×単価 を小数2桁のまま。丸めない
      締め済みの月には登録も取消もできない。先にタイ締めでその月を取り消す

  タイ納品一覧 (frmThaiNohinIchiran)
    経理で見るための画面。明細 / 得意先ごとのまとめ を切り替えられる。
    見るたびに集計しなおすので、締めるまでは数字が動く。

  タイ締め (frmThaiShime / T_TH_SHIME)
    年月を選んで「締める」。月末で全得意先をまとめて締める。得意先ごとに1件できる。
    得意先ごとの月の合計に四捨五入を1回掛けたバーツが締め金額。
    納品に締めNo(SHIME_NO)が書かれ、それが入った納品は拾わないし取り消せない。
    締め取消も月ごと。得意先1社だけの取消はできない。
    月が終わる前に締めようとすると確認が出る。

5. 数字の決まりごと
------------------------------------------------------------

  ここは経理のExcelと同じになるように作った。直すときに崩さないこと。

  丸め (modCommon.Marume)
    得意先マスタの丸め区分で 切り捨て / 四捨五入。
    四捨五入は Int(x + 0.5)。Math.Round は .5 が偶数側に丸まって経理と合わないので使っていない。
    納品の金額は丸めずに持って(T_NOHIN.KINGAKU decimal(13,2))、
    締めのときに月の合計へ1回だけ掛ける。1行ずつ丸めると東北機械のように
    単価に小数がある得意先で数円ずれる。
    請求書の明細の金額は表示だけ整数に丸めているので、足し上げると計と合わないことがある。
    それでいい(経理のExcelも同じ。計のほうがExcelと合っていることが大事。田島さんに確認済み)。

  請求先
    納品は得意先コードに付く。締めと請求書と入金は請求先コードに付く。
    請求先 = 得意先マスタの請求先コード。空ならその得意先自身。
    締めの対象は ISNULL(NULLIF(請求先,''), 得意先) = 請求先 で拾っている(frmShime.TaishoJoken)。

  締めの期間 (modCommon.ShimebiOf / KaishibiOf)
    締め日 = 選んだ年月の締日。末日(31)はその月の実際の末日(2月は28日か29日)。
    開始日 = 前月の締め日の翌日。
    年月の意味: 「2017年2月」を選ぶと
      末日締め   2/1  ～ 2/28
      20日締め   1/21 ～ 2/20
      25日締め   1/26 ～ 2/25
    T_SEIKYU.SHIME_YM にはこの年月(201702)が入る。

  締めの対象
    取消でない / 請求書番号が空 / 納品日が期間内 の納品。
    一覧を出すときと締めるときで条件がずれると二重請求になるので、TaishoJoken に1か所にまとめてある。

  請求書の数字 (frmShime)
    前回請求額 = その請求先の1つ前の締め(締め日が前のもの)の今回請求額。無ければ開始残高
    入金額     = 期間内(開始日～締め日)に入った入金の合計
    繰越額     = 前回請求額 - 入金額
    今回売上額 = 期間内の納品の金額の合計に丸めを掛けたもの
    消費税     = Int(今回売上額 × 税率)  ※端数は丸め区分に関係なく切り捨て
    今回請求額 = 繰越額 + 今回売上額 + 消費税
    締めた時点の値が T_SEIKYU に入り、その後は動かない。締め済みの行は T_SEIKYU の値をそのまま出す。

  消費税 (modCommon.ZeiritsuOf / frmShime.ShohizeiOf)
    税率は納品日で決める。今日の日付ではない(締め直したときに過去の月が変わると困るため)。
    2014/04/01 から 8%、それより前は 5%。日付は modCommon.ZEI_KAISEIBI。
    20日締め・25日締めは2014年4月の締めが 3/31 と 4/1 をまたぐので、
    3/31までの納品分に丸めを掛けて5%、売上額からそれを引いた残りに8%、を足している。
    ※ShohizeiOf は「境目は1つ」の前提で書いてある。「8.」を見ること。

  請求書番号 (frmShime.SeikyuSaiban)
    年度2桁-連番4桁 (16-0001 など)。年度は4月始まり。4月になったら 0001 に戻る(田島さん)。
    年度は締め処理画面の「発行日」で決まる。3月分を4月に締めると新しい年度の番号になる。
    取り消した請求も残すので、その番号は欠番。

  納品No / 入金No / タイ納品No / タイ締めNo
    MAX + 1 の6桁(000001)。同時に登録するとまれに重複するので3回まで取り直す。
    「採番に失敗しました」はもう一度やれば通る。

  請求書 (frmSeikyusho.SetMeisai と 請求書レイアウト覚書.txt)
    1枚15行。足りない分は空行で埋める。0件でも1枚。
    レポートには全部文字列で渡す。計はVB側で入れる。レポートで足し上げないこと。
    発行日は和暦をVB側で作っている。

  タイ
    納品は小数2桁のまま(丸めない)。締めで得意先ごとの月の合計に四捨五入を1回。
    通貨は混ぜずにそのまま足している。今のところバーツしか来ていない。
    円には直していない。レートも持っていない。

6. 月初にやっていること (田島さんに聞いた)

  1日か2日に、

7. 止まったときに見るところ
------------------------------------------------------------

  この3年間、止まったことは無い。なので下は「たぶんこう」というもの。
  エラーは全部 MsgBox で ex.Message をそのまま出しているので、まず出た文を読むこと。

  起動しない / どの画面でも「エラーが発生しました」
    → SVR01 が動いているか。SQL Server (SQLEXPRESS) のサービスが上がっているか。
      共有フォルダの exe が見えているか。modCommon.CONN_STR。

  「請求書のレポートがありません」
    → exe と同じフォルダに rptSeikyusho.rpt が無い。

  請求書発行だけエラー / 画面が開かない
    → そのPCに Crystal Reports (10.5) が入っていない。他のPCで出せるか試す。

  締め処理で「既に締められています」
    → その請求先・その月は締め済み。一覧の請求書Noを見る。二度締めはできないようにしてある。

  締め取消で「後の締めが残っています」
    → 新しいほうから順に取り消す。

  納品取消で「請求書 xx で締め済みです」
    → 先に締め処理でその請求を取り消す。

  受注取込で「要確認」
    → 納品済みの受注が生産管理側で変わっている。上書きしていない。田島さんに見てもらう。
  受注取込で「得意先 xx が登録されていません」
    → 得意先登録で入れてから、もう一度同じファイルを取り込む(重複は何もしないので大丈夫)。

  締め処理で「期間より前に、まだ請求していない納品が n 件」
    → 納品日が古い納品が請求されずに残っている。納品日の打ち間違いか、締め忘れ。
      締め処理の下の一覧では出ないので、SQLで T_NOHIN を SEIKYU_NO IS NULL で見る。

  「初回」の確認が出る
    → 新しい請求先。前回請求額が得意先登録の開始残高(たいてい0)から来ている。
      今動いている得意先は全部締め済みなので、新規のときだけ出るはず。

  タイ納品入力で「タイ締めで締め済みです」
    → 納品日の月が締め済み。日付を確かめる。その月に入れるならタイ締めで取り消す。

  SQLで直すとき
    T_NOHIN.SEIKYU_NO     入っていれば請求済み。空なら未請求
    T_TH_NOHIN.SHIME_NO   同じ。入っていれば締め済み
    T_SEIKYU / T_TH_SHIME 締め1件。TORIKESHI_KBN='1' は取り消したもの(残してある)
    T_NOHIN / T_NYUKIN / T_TH_NOHIN の TORIKESHI_KBN='1' は取り消したもの
    どの表も KOSHIN_USER / KOSHIN_DT に最後に触った人と日時が入っている
    直したら締め処理の一覧を出しなおして数字を見ること。

9. ソースを読むときに
------------------------------------------------------------

  ・Option Strict Off。Val / CStr / ToStr で行き来している。
  ・SQLは全部文字列で組み立てている。パラメータは使っていない。
    「'」は EscQuote。空なら NULL は NullIfEmpty / ToSqlDate。
  ・Microsoft.VisualBasic.Day / Left / Right と書いてあるのは、
    フォームに同じ名前のものがあってそのままでは通らないため。
  ・mblnShori はボタンの連打対策。mblnLoad は Load 中にイベントで一覧を出しなおさないため。
  ・締めと締め取消だけトランザクションを使っている。請求を作るのと納品に番号を書くのが
    片方だけ通ると二重請求になるため。ほかは1文ずつ投げている。
  ・タイの画面は日本の画面をコピーして直したもの。
    日本の画面は動いているので、タイを作るときも触らなかった。同じ直しが要るときは両方。
  ・備品管理(\\SVR01\share\dev\BihinKanri\)と同じ書き方で書いてある。

10. 分からないこと (ソースに無い)
------------------------------------------------------------

  ・日本の受注CSVの7列目(KBN)。取り込んで T_JUCHU.KBN に入れているが、何にも使っていない。
    何の区分かはソースにも書いていない。生産管理の業者は廃業しているので聞ける人がいない。
  ・タイの受注CSVの9列目(KBN)も同じ。タイ納品入力の受注一覧に「区分」で出しているだけ。
    10列目(状態)は X が取消ということしか分かっていない。X 以外に何が来るかは知らない。
  ・タイの受注CSVが今どうやって共有フォルダに届いているか。
    作ったときは中村さんが現地からもらってきたものを置いてもらっていた(2011年のコメント)。
    今は取込を小林さんがやっている。経路は確かめられなかった。中村さんに聞くこと。
  ・生産管理システムが毎晩CSVを出している設定。前任者の時代に誰かが設定したもので、経緯は分からない。
    これが止まると受注取込ができない。
  ・得意先マスタの支払条件(SHIHARAI)は持っているだけで、どこにも使っていない。
    見るための備考のようなもの。
